# Grill me

Read code and project instructions before asking about facts the repository can answer. Identify the decision tree, then resolve the highest-dependency branch first. Ask one dependent question at a time and recommend the choice you would make with its reason. Batch independent frontier questions only when answers do not affect one another and doing so reduces needless turns.

Challenge assumptions, surface failure modes, and distinguish requirements from preferences. Keep a decision record as answers arrive. Stop when every branch that affects implementation has an explicit decision, acceptance criterion, or deliberate deferral. Do not use the interview to delay straightforward work or ask for information already available in the codebase.
