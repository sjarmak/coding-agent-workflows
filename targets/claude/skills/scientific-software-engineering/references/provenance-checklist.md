# Provenance & FAIR Review Checklist

Concrete gates for reviewing a scientific pipeline, dataset, or API. Use as
the working checklist behind SKILL.md; each unchecked box is a finding.

## Provenance chain

- [ ] Every derived artifact records: input identifiers/hashes, code commit,
      parameters, environment spec, generation date.
- [ ] Raw data is immutable and separately stored from derived products.
- [ ] Any artifact can be regenerated by a single documented command.
- [ ] Pipeline stages declare inputs/outputs; no stage reads undeclared state.
- [ ] Nondeterministic steps are identified, seeded, or bounded with rationale.

## Reproducibility

- [ ] Dependencies pinned (lockfile or container digest), including system libs
      for numerical code (BLAS/LAPACK variants change results).
- [ ] Golden-dataset regression test: small pinned input, expected output
      within stated tolerance, run in CI.
- [ ] A stranger-readable REPRODUCING.md (or equivalent) exists for any
      published result.

## Numerical correctness

- [ ] No float equality; every tolerance has a written justification.
- [ ] Validation anchor exists: analytic case, published reference values, or
      independent implementation — cited.
- [ ] Units and frames carried in types/metadata (astropy units, column
      metadata), not comments.
- [ ] Edge regimes tested: NaN/missing propagation, catastrophic cancellation,
      overflow, empty inputs, single-element inputs.

## FAIR / metadata

- [ ] Persistent identifiers on datasets and software releases (DOI, bibcode).
- [ ] Community vocabulary used where one exists (e.g. UAT); local terms
      mapped, not invented.
- [ ] License + citation file (CITATION.cff) present.
- [ ] Schema changes are versioned migrations with downstream-consumer notes.

## Long-lived API surfaces

- [ ] Response schemas versioned; breaking changes gated behind a version, not
      a deploy.
- [ ] Deprecations announced with dates and migration notes; nothing removed
      while still measurably used.
- [ ] Rate limits, auth, and pagination documented — the undocumented parts
      are the ones scripts break on.
